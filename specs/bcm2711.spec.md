# Broadcom BCM2711

## Orientation

The BCM2711 is the SoC of the Raspberry Pi 4 Model B, the Raspberry Pi 400 and Compute Modules 4
and 4S: four 64-bit Cortex-A72 cores beside a VideoCore VI GPU. The VideoCore and its firmware
own the boot; the Arm cores start only after the firmware has loaded a stub, a
device tree and a kernel. Peripherals sit in a 64 MB "Main peripherals" window plus an
Arm-only "ARM Local" block, and the Arm cores see them at one of two addresses depending on
whether the firmware enables Low Peripheral mode. A public datasheet (BCM2711 ARM Peripherals)
covers the blocks the Arm side may drive: interrupts, GPIO, the UARTs, SPI, I2C, DMA, PWM, PCM
and the timers. It omits the GPU-controlled blocks, the Ethernet MAC, the EMMC2 controller and
PCIe. This spec rests only on documents. Facts read from the Raspberry Pi boot stub's source
(timer frequency, `SCR_EL3`, the entry exception level and the stub's patch words) are in an
overlay in `hardware-specs-permissive`. Device-tree facts (compatibles, clock names, the CPU
nodes' enable method) are not here: every BCM2711 device-tree file in Linux is `GPL-2.0` only.
The `instances:` table is empty until IP specs for the PL011 and the other blocks exist.

## Quick-facts

- **Addressing model.** The chip has a full 35-bit address map, seen by the Arm cores and by
  "large address" masters such as the DMA4 engines, and a 32-bit "legacy master" view seen by
  the other DMA masters. The datasheet gives every peripheral address in the legacy view. In the
  full map, Main peripherals are `0x4_7C00_0000`–`0x4_7FFF_FFFF` and ARM Local peripherals
  `0x4_C000_0000`–`0x4_FFFF_FFFF`. When the VideoCore enables Low Peripheral mode, the Arm cores
  alone see Main peripherals at `0x0_FC00_0000`–`0x0_FF7F_FFFF` and ARM Local at
  `0x0_FF80_0000`–`0x0_FFFF_FFFF`. Translation: legacy `0x7Enn_nnnn` is full-map
  `0x4_7Enn_nnnn` and Low Peripheral `0x0_FEnn_nnnn`, so UART0 at legacy `0x7E20_1000` is
  `0x0_FE20_1000` in Low Peripheral mode. `[databook]` (BCM2711 ARM Peripherals, §1.2.1–1.2.4,
  pp. 4–6, and §11.5, pp. 146–147)
- **Peripheral mode selection.** `arm_peri_high=1` in `config.txt` selects high peripheral mode
  (the full-map addresses), and the firmware also selects it on its own when it loads a device
  tree that suits it. Turning it on without a matching device tree stops the board booting, and
  the stub the firmware supplies does not support it, so an `armstub` of your own is needed.
  `[doc]` (Raspberry Pi documentation, legacy config.txt boot options, `arm_peri_high`)
- **RAM.** Arm RAM starts at physical `0x0` and runs to the installed size; the VideoCore's share
  is taken from below `0x0_4000_0000` downward, sized by a `config.txt` setting. Parts carry up
  to 8 GB of LPDDR4. `[databook]` (BCM2711 ARM Peripherals, §1.2.3, p. 5), `[doc]` (Raspberry
  Pi documentation, BCM2711 processor page)
- **DMA view of memory.** Legacy DMA engines must use legacy addresses: RAM through a 1 GB window
  at `0xC000_0000`–`0xFFFF_FFFF`, movable over the rest of SDRAM with the PAGE or PAGELITE bits;
  the VPU L2-cache aliases at `0x0000_0000` (allocating) and `0x8000_0000` (non-allocating)
  reach only the first 1 GB and cannot be moved. Peripherals are at `0x7C00_0000`–`0x7FFF_FFFF`
  in this view. `[databook]` (BCM2711 ARM Peripherals, §1.2.4, p. 6)
- **Boot chain.** The boot ROM loads a second-stage bootloader from the SPI EEPROM; that stage
  sets up clocks and SDRAM, reads its EEPROM configuration and walks `BOOT_ORDER` (SD, network,
  USB mass storage and others) to load the VideoCore firmware, which for Raspberry Pi 4-series
  boards is the `start4*.elf` family. The firmware chooses and edits the device tree, loads the kernel (`kernel8.img` by
  default, as `arm_64bit` defaults to 1 on BCM2711 boards; 64-bit kernels go to `0x200000`
  unless `kernel_address` says otherwise) and runs an Arm stub before it. The default stub is
  built into the firmware and chosen per model; `armstub=` names a replacement file. `[doc]`
  (Raspberry Pi documentation, EEPROM boot flow; config.txt boot options, `kernel`, `arm_64bit`,
  `armstub`; legacy config.txt boot options, `kernel_address`; boot folder contents)
- **Stub load and hand-off words.** A stub file (`armstub8.bin`, or the file `armstub=` names) is
  loaded to the start of DRAM (address `0x0`) and run in AArch64 at EL3; when the stub image
  carries a magic value, the firmware writes the kernel and device-tree load addresses into
  memory words near the start of memory, where the stub reads them. `[doc]` (Trusted Firmware-A documentation, Raspberry Pi 4 platform,
  "TF-A port design") `TODO (verify on hardware)`: the offsets of those words; the permissive
  overlay gives them from the stock stub's source.
- **Kernel entry contract.** Whatever stub runs must enter an arm64 kernel with `x0` = the
  device-tree physical address and `x1`–`x3` = 0, all of DAIF masked, the MMU off, in
  non-secure EL2 (recommended) or EL1, with `CNTFRQ` programmed and `CNTVOFF` consistent across
  cores. `[standard]` (Linux arm64 boot protocol, booting.rst, "Call the kernel image")
  `TODO (verify on hardware)`: the state the stock stub actually hands over; no Raspberry Pi
  document states it.
- **PSCI through TF-A.** No document describes PSCI for the stock stub. Trusted Firmware-A has a
  BL31-only port (`PLAT=rpi4`) loaded through `armstub=`: it enters the payload at AArch64 EL2
  with the device-tree address in `x0`, and patches the device tree to advertise PSCI and to
  reserve its own resident memory. The port's documentation warns it is not secure, since all its
  memory is DRAM the non-secure world can reach. `[doc]` (Trusted Firmware-A documentation,
  Raspberry Pi 4 platform)
- **SMP topology.** Four Cortex-A72 cores (Armv8-A), each with 32 kB data and 48 kB instruction
  L1 cache, sharing a 1 MB L2. `[doc]` (Raspberry Pi documentation, BCM2711 processor page)
  `TODO (verify on hardware)`: the MPIDR values and the secondary-core release method; the
  permissive overlay covers the stock stub's spin-table.
- **Interrupt controller.** A GIC-400 is the controller by default; `enable_gic=0` in
  `config.txt` routes interrupts through the legacy controller instead. The GIC-400 is configured
  for 4 CPUs and 192 SPIs. Its base is the Arm-only address `0x4_C004_0000`, or `0xFF84_0000` in
  Low Peripheral mode. `[databook]` (BCM2711 ARM Peripherals, §6.1, p. 85; §6.3, p. 89; §6.5.1,
  p. 92), `[doc]` (Raspberry Pi documentation, legacy config.txt boot options, `enable_gic`)
  `TODO (verify on hardware)`: the distributor and CPU-interface offsets inside that block, which
  the GIC-400 TRM gives and this spec did not read.
- **Interrupt IDs at the GIC.** Per core: hypervisor timer PPI 26, virtual timer 27, the legacy
  controller's FIQ 28, secure physical timer 29, non-secure physical timer 30, the legacy
  controller's IRQ 31. Shared: ARM_LOCAL mailboxes 32–47, core 0–3 PMU 48–51, AXI error 52,
  local timer 53, ARMC peripheral interrupts 64–79, VideoCore peripheral interrupts 96–159 (ID =
  96 + the VC IRQ number), ETH_PCIe L2 interrupts 160–216. These are GIC interrupt IDs, not
  device-tree cell values. `[databook]` (BCM2711 ARM Peripherals, §6.3, Figure 7, p. 89)
- **Shared interrupt lines.** VC IRQ 57 is the OR of all five PL011 UARTs (GIC ID 153), 53 of all
  I2C controllers (149), 54 of all SPI controllers (150), 29 of the auxiliary block's mini UART
  and SPI1/SPI2 (125), and 62 of EMMC and EMMC2 (158); 23, 24 and 46 also pair two peripherals.
  The UART, SPI and I2C sources behind 53, 54 and 57 are told apart in `PACTL_CS` (legacy
  `0x7E20_4E00`), the auxiliary ones in `AUX_IRQ`. `[databook]` (BCM2711 ARM Peripherals,
  §6.2.4, Table 102 and Figure 6, pp. 86–88)
- **Debug UART.** UART0 is an Arm PL011 (the datasheet names the r1p5 TRM) at legacy
  `0x7E20_1000` (`0xFE20_1000` in Low Peripheral mode); UART2–5 are further PL011s at
  `0x7E20_1400`, `…1600`, `…1800`, `…1A00`. Registers are 32-bit words (DR `0x00`, FR `0x18`,
  IBRD `0x24`, FBRD `0x28`, LCRH `0x2C`, CR `0x30`, IMSC `0x38`, ICR `0x44`). FIFOs are 32×8
  transmit and 32×12 receive; IrDA is absent; only CTS/RTS of the modem lines exist. UART0's
  TXD0/RXD0 are GPIO14/15 in ALT0. Interrupt: VC IRQ 57, GIC ID 153, shared by all five.
  `[databook]` (BCM2711 ARM Peripherals, §11.1, p. 144; Table 171, p. 145; §11.5, Table 172,
  pp. 146–147; §6.2.4, p. 87)
- **Early console.** Raspberry Pi's documented early console for BCM2711 boards is
  `earlycon=pl011,mmio32,0xfe201000` (UART0) or `earlycon=uart8250,mmio32,0xfe215040` (the mini
  UART), at 115200 baud by default. The firmware's initial UART0 clock is 48 MHz
  (`init_uart_clock`, UART0 only, baud at most a sixteenth of it) and its initial baud 115200
  (`init_uart_baud`). `[doc]` (Raspberry Pi documentation, UARTs, "Enable early console for
  Linux"; legacy config.txt boot options, `init_uart_clock` and `init_uart_baud`)
- **Mini UART.** UART1 is the mini UART in the auxiliary block at legacy `0x7E21_5000` (shared
  with SPI1 and SPI2 and enabled through `AUX_ENABLES` at `+0x04`); its data register
  `AUX_MU_IO_REG` is at `+0x40`. Its clock is the VPU core clock, so its baud rate moves when the
  core frequency changes unless the core clock is fixed. `[databook]` (BCM2711 ARM Peripherals,
  §2.1, Table 2, p. 8), `[doc]` (Raspberry Pi documentation, UARTs, "Mini UART and core
  frequency")
- **Timers.** Each core's generic timer raises secure and non-secure physical, hypervisor and
  virtual timer interrupts (PPIs above). ARM_LOCAL `ARM_CONTROL` bit 7 drives the cores' system
  counter from the crystal (0, the reset value) or the AXI/APB clock, and bit 8 makes it count by
  one or two. The System Timer at legacy `0x7E00_3000` has a 64-bit free-running counter and four
  32-bit compare channels (VC IRQ 0–3, GIC ID 96–99); the SP804-like ARM timer at legacy
  `0x7E00_B000` runs from the variable system clock, so the datasheet advises the System Timer
  for accurate timing. `[databook]` (BCM2711 ARM Peripherals, §6.2.1, p. 86; §6.5.2, Table 105,
  p. 93; §10.1, p. 142; §12.1, p. 159) `TODO (verify on hardware)`: the crystal frequency, which
  the datasheet does not give; read `CNTFRQ_EL0`, and see the permissive overlay for the value
  the stock stub programs.
- **ARM_LOCAL block.** Arm-only registers at `0x4_C000_0000`, or `0xFF80_0000` in Low Peripheral
  mode: the timer and AXI-error controls, per-core timer and mailbox interrupt routing, per-core
  IRQ and FIQ source registers at `+0x60` and `+0x70`, and sixteen Arm-to-Arm mailboxes
  (`MBOX_SET00` at `+0x80`). These mailboxes are not the VideoCore mailboxes in the ARMC block.
  `[databook]` (BCM2711 ARM Peripherals, §6.5.2, Table 104, p. 92; §13.1–13.2, p. 163)
- **Clocks and power.** The UART clock source and dividers belong to the Clock Manager, which
  the datasheet does not describe beyond the general-purpose GPIO clock generators. The Arm side can query and
  set peripheral clocks through the VideoCore mailbox property channel (channel 8): tag `0x00030002` gets a clock's rate
  and `0x00038002` sets it, with clock IDs such as 2 (UART), 1 (EMMC) and 12 (EMMC2). Rates there
  are the peripherals' base clocks, before the peripherals' own dividers. `[databook]` (BCM2711
  ARM Peripherals, §5.4, p. 81; §11.1, p. 144), `[doc]` (Raspberry Pi firmware wiki, Mailbox property
  interface, "Clocks") `TODO (verify on hardware)`: the VideoCore mailbox's register base on
  this chip, which neither document gives.
- **GPIO and pinmux.** 58 GPIOs in three banks (0–27, 28–45, 46–57), one register block at
  legacy `0x7E20_0000`: function select `GPFSEL0`–`GPFSEL5` at `0x00`–`0x14`, set/clear/level at
  `0x1C`/`0x28`/`0x34`, and pulls in `GPIO_PUP_PDN_CNTRL_REG0`–`3` at `0xE4`–`0xF0`, two bits per
  pin (00 none, 01 pull-up, 10 pull-down). The block has four interrupt lines, one per bank and
  one shared, which are VC IRQ 49–52 (GIC ID 145–148). `[databook]` (BCM2711 ARM Peripherals,
  §5.1, p. 65; §5.2, Table 63, p. 66; Table 90, p. 74; §6.2.4, p. 87)
- **Peripheral memory ordering.** The AXI system may return reads out of order when software
  moves from one peripheral to another: put a write barrier before the first write to a
  peripheral and a read barrier after the last read, including at interrupt-handler entry and
  exit. `[databook]` (BCM2711 ARM Peripherals, §1.3, pp. 6–7)
- **DTB runtime patching.** The firmware picks the device tree by board revision, edits it,
  applies `config.txt` parameters and overlays, and passes the kernel a pointer to the merged
  tree; it passes its own parameters in `/chosen`. Parse the live tree, not the source.
  `[doc]` (Raspberry Pi documentation, boot folder and Device Trees, "Device Trees, overlays, and
  parameters" and "Firmware parameters")

## Gotchas

- **The GIC and ARM_LOCAL bases are not legacy addresses.** Every other address in the datasheet
  is a legacy master address to translate; these two are Arm-only and translate differently
  (`0x4_C004_0000` or `0xFF84_0000` for the GIC). `[databook]` (BCM2711 ARM Peripherals, §6.5.1
  and §6.5.2, p. 92)
- **One GIC line serves many blocks.** All five PL011s raise GIC ID 153, all I2C controllers 149,
  all SPI controllers 150, EMMC and EMMC2 158; a handler must read each block's status (or
  `PACTL_CS`). The 57 ETH_PCIe interrupts reach the GIC individually, but the legacy controller
  sees only their OR (VC IRQ 58). `[databook]` (BCM2711 ARM Peripherals, §6.2.4–6.2.5,
  pp. 87–89)
- **Peripheral mode is a three-way agreement.** High peripheral mode needs a device tree written
  for it and a stub that supports it; a mismatch stops the boot. `[doc]` (Raspberry Pi
  documentation, legacy config.txt boot options, `arm_peri_high`)
- **Pulls are set through `GPIO_PUP_PDN_CNTRL_REG0`–`3`.** They are the only pull registers in
  the GPIO register table, written directly with two bits per pin; reading them returns the
  current pull state. `[databook]` (BCM2711 ARM Peripherals, §5.2, Table 63, p. 66; Table 90,
  p. 74)
- **Legacy DMA reaches 1 GB at a time.** Above the first 1 GB of SDRAM, a legacy DMA engine
  needs its PAGE bits moved, and the L2-cached aliases never reach past it. `[databook]` (BCM2711
  ARM Peripherals, §1.2.4, p. 6)
- **The mini UART's baud rate follows the core clock.** Use UART0 (PL011) for a console that must
  survive frequency changes, or fix the core clock. `[doc]` (Raspberry Pi documentation, UARTs,
  "Mini UART and core frequency")
- **Not the Pi 5 chip.** The Raspberry Pi 5 family uses the BCM2712, its successor; nothing here
  applies to it. `[doc]` (Raspberry Pi documentation, BCM2712 processor page)
