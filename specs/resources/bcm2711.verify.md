# Verification of `bcm2711`

All six PDFs matched the SHA-256 values recorded in the spec's `docs` entries. The Arm
documentation-service `latest` JSON for ddi0471, ihi0048, ddi0487 and ddi0183 named revisions b,
bb, md and g. Printed page numbers were checked against the PDF footers (BCM2711 PDF page =
printed page + 1). GIC interrupt IDs of the form 96 + n and 160 + n are read from Figure 7
(p. 89) as order-preserving maps of the 64 VC lines onto 96–159 and the 57 ETH_PCIe lines onto
160–216. The datasheet text never states the per-line formula, and nothing in it contradicts
that reading.


This record is a delta verification. The spec changed from 6d3790f to e7529fe only in
Quick-facts/5, /10, /11, /16 and Gotchas/1, /3, /5 (`git diff 6d3790f e7529fe --
specs/bcm2711.spec.md`); those seven lines were verified afresh on 2026-10-08 against freshly
fetched copies of the BCM2711 datasheet, the GIC-400 TRM and IHI 0048B (SHA-256 values again
matching the spec's `docs` entries), the five Raspberry Pi documentation pages at
42deaefbc8b4edfe342b0d759ec16cda3be5e7d8, and booting.rst at Linux
8d3ae59288f1e7d58d76558a6ee96d533bc5019f. Every other line is carried unchanged from the 6d3790f
record, whose only FAILs were on the changed bullets.

A further delta at 90b3562: `git diff e7529fe 90b3562 -- specs/bcm2711.spec.md` changes only
Quick-facts/16's citation, adding the "Enable additional UARTs on Raspberry Pi 4, 400, CM4, and
CM4S" section. Quick-facts/16 was verified again against that section on 2026-10-08; every other
line is carried unchanged from the e7529fe record.

- Quick-facts/1 "Addressing model": PASS — 35-bit and legacy views, full-map Main and ARM Local
  ranges, Low Peripheral ranges, the 0x7Enn→0x4_7Enn/0x0_FEnn translation and UART0 at legacy
  0x7E20_1000 match §1.2.1–1.2.4 (pp. 4–6) and §11.5 (pp. 146–147). The GIC and ARM_LOCAL exceptions
  match §6.5.1–6.5.2 (p. 92).
- Quick-facts/2 "Peripheral mode selection": PASS — `arm_peri_high` text (automatic with a
  suitable DTB, boot failure without one, stub support missing so `armstub` needed) matches the
  legacy boot options page. The inference's premises hold (Figure 1 and §1.2.2–1.2.3 give the Arm
  only the full map and Low Peripheral mode), and its conclusion is tagged and carries a TODO.
- Quick-facts/3 "RAM": PASS — RAM from 0x0, VC share from 0x0_4000_0000 downward sized by
  config.txt (§1.2.3, p. 5). Up to 8 GB LPDDR4 (BCM2711 processor page). `/memory`,
  `/reserved-memory` exclusion, `no-map`/`reusable` semantics, reservation block and DTB
  non-overwrite rule match DT spec v0.4 §3.4, §3.5 and §5.3.
- Quick-facts/4 "DMA view of memory": PASS — legacy RAM window 0xC000_0000–0xFFFF_FFFF, movable
  with PAGE/PAGELITE, fixed L2 aliases at 0x0 and 0x8000_0000 limited to the first 1 GB, and
  peripherals at 0x7C00_0000–0x7FFF_FFFF (§1.2.4, p. 6). ENABLE.PAGE 27:24 (DMA0–6) and PAGELITE
  31:28 (DMA7–10) (Table 62, p. 60). DMA4 bypasses paging (§4.6, p. 64). Channel 15 at 0x7EE0_5000,
  VPU-only (§4.2, p. 31).
- Quick-facts/5 "Boot chain": PASS — ROM→EEPROM second stage, clocks/SDRAM, EEPROM config,
  BOOT_ORDER modes (EEPROM boot flow page, "Second stage bootloader"). `start4*.elf` for the
  4-series (boot folder contents). `kernel8.img` default and `arm_64bit`=1 on Pi 4/400/CM4/CM4S,
  built-in default stub chosen per model and settings, and `armstub=` (config.txt boot options).
  64-bit kernels at 0x200000 by default, with `kernel_address` overriding and `kernel_old`
  loading to 0x0 (legacy boot options, `kernel_address` and `kernel_old`). DTB chosen by board
  revision and edited by the firmware ("Device Trees, overlays, and parameters").
- Quick-facts/6 "Stub load and hand-off words": PASS — load to address 0, AArch64 EL3, magic value
  causing the kernel and DTB load addresses to be written near the start of memory: TF-A rpi4.rst
  "TF-A port design".
- Quick-facts/7 "Kernel entry contract (Linux's requirements)": PASS — x0–x3, DAIF, MMU off, NS
  EL2/EL1, CNTFRQ/CNTVOFF, EL1PCTEN, DTB alignment and size, text_offset/image_size placement, DMA
  quiesce, PoC clean, coherency, same EL, SCR_EL3.FIQ and HCE all match booting.rst "Setup the
  device tree" and "Call the kernel image". booting.rst adds "where available" to EL1PCTEN, which
  changes nothing on a core that implements EL2.
- Quick-facts/8 "PSCI through TF-A": PASS — BL31-only `PLAT=rpi4` via `armstub=`, AArch64 EL2
  entry with the DTB in x0, DT patched for PSCI and a reserved-memory node, and the "not secure"
  warning all match rpi4.rst.
- Quick-facts/9 "SMP topology": PASS — core count, cache sizes and Armv8-A match the processor page.
  MPIDR_EL1 fields match A72 TRM §4.3.2 Table 4-17 (pp. 4-91–4-92). SMPEN bit 6, reset 0, the
  set-before rule, the I-cache/TLB-broadcast scope and coherence regardless of SMPEN match §4.3.67
  Table 4-79 (p. 4-208) and §5.5 (p. 5-281).
- Quick-facts/10 "Secondary-core release (Linux's protocol)": PASS — booting.rst (the CPU
  enable-method bullets at the end of "Call the kernel image"): an `enable-method` per cpu node;
  `cpu-release-addr` a naturally aligned, zero-initialized 64-bit location that "must be
  contained in the reserved region"; CPUs "should spin outside of the kernel" in `/memreserve/`
  memory; a single 64-bit little-endian write and a `sev` from the primary CPU; psci CPUs "should
  remain outside of the kernel", CPU_ON per ARM DEN 0022A, and the tree "should contain a 'psci'
  node". x0–x3 = 0 per "Secondary CPU general-purpose register settings". The must/should
  strengths now match the text. "Stays outside the kernel's memory" reads as the protocol's
  description of the same "should remain", not a stronger requirement.
- Quick-facts/11 "Interrupt controller": PASS — GIC-400 selected by default and the legacy
  controller selectable from config.txt (§6.1, p. 85; §6.3, p. 89; `enable_gic` on the legacy
  boot options page, default 1). Base 0x4_C004_0000 / 0xFF84_0000 and NUM_CPUS=4, NUM_SPIS=192
  (§6.5.1, p. 92). Distributor +0x1000, CPU interfaces +0x2000–0x3FFF, virtual interface control
  +0x4000–0x5FFF, virtual CPU interfaces +0x6000–0x7FFF (GIC-400 TRM §3.2 Table 3-1, p. 3-3); the
  derived Low Peripheral and full-map addresses are the base plus those offsets. GICv2 compliance
  and the GICv2 Security Extensions are now located at GIC-400 TRM §1.2 "Compliance" (p. 1-4),
  with §1.1 (p. 1-2) naming both extensions. IHI 0048B chapter 3 is "Interrupt Handling and
  Prioritization" and chapter 4 "Programmers' Model". The earlier missing-locator FAIL is
  resolved.
- Quick-facts/12 "Interrupt IDs at the GIC": PASS — PPI 25–31 sources match GIC-400 TRM §2.3.2
  Table 2-3 and datasheet Figure 7. SPI blocks 32–47, 48–51, 52, 53, 64–79, 96–159 and 160–216
  match Figure 7 (p. 89). AVS, PCIe INTA–D, MSI, GENET A/B and XHCI numbers match Table 103
  (p. 88) plus 160. PPI active-low level and SPI rising-edge/active-high match §2.3.2–2.3.3
  (p. 2-8).
- Quick-facts/13 "Shared interrupt lines": PASS — VC 57/53/54/29/62 groupings, the 23/24/46 pairs,
  PACTL_CS at 0x7E20_4E00, and Figure 6 routing SPI1/SPI2 through AUX_IRQ to 29 despite Table 102's
  "OR of all SPI" label all match §6.2.4 (pp. 86–88; the figure was checked as an image) and §2.1.
  The GIC IDs follow Figure 7.
- Quick-facts/14 "Debug UART": PASS — r1p5 TRM named, base addresses, register offsets, FIFO sizes,
  no IrDA, CTS/RTS only (§11.1, §11.5 Table 172, Table 173 bit table). TXD0/RXD0 on GPIO14/15 ALT0
  (Table 171, p. 145). VC 57 / GIC 153 (§6.2.4, Figure 7). Low Peripheral address per §1.2.4.
- Quick-facts/15 "PL011 programming order": PASS — disable before reprogramming (§3.3.1 note,
  p. 3-6). CR sequence (§3.3.8, p. 3-16). IBRD/FBRD latched by the LCR_H write (§3.3.7, p. 3-14).
  Transition-through-level interrupts (§3.3.9, p. 3-17), and no TX interrupt when enabled with an
  empty FIFO (§2.8.3 note, p. 2-23). §2.8.3's own first bullet, and the BCM2711 datasheet's §11.4
  copy of it, word the TX interrupt as level-based without the note. The TRM's note settles this,
  so it is not counted as contrary evidence.
- Quick-facts/16 "Which UART is the console": PASS — everything the bullet states matches the
  UARTs page: Pi 4 primary UART1 on GPIO14/15 (pins 8 and 10) with UART0 on Bluetooth ("Primary
  and secondary UARTs" table); `disable-bt` and `miniuart-bt` making UART0 primary, the
  `core_freq=250`/`force_turbo=1` requirement and the reduced Bluetooth baud (the two Bluetooth
  overlay sections); `enable_uart` defaults by primary type and the fixed core clock ("Mini UART
  and core frequency"); 3.3 V ("UART types"). The Compute Module sentence describes the page
  correctly: its "UART types" prose says all Compute Module UARTs are off by default, while the
  "UART by Raspberry Pi model" table lists only UART2–5 as disabled for CM4/CM4S and the
  primary/secondary table gives Compute Module 4 UART0; the TODO carries the CM4/CM4S defaults
  and the Pi 400 / CM4S assignment, which those tables do not list. "UART2–5 are off ... until an
  overlay enables them" is now located: the model table marks them disabled by default, and the
  newly cited "Enable additional UARTs on Raspberry Pi 4, 400, CM4, and CM4S" says the `uart2`–
  `uart5` overlays enable them on all four models. The earlier missing-locator FAIL is
  resolved.
- Quick-facts/17 "Early console": PASS — both `earlycon` strings and the 115200 default (UARTs,
  "Enable early console for Linux"). The 48 MHz, UART0-only, at-most-a-sixteenth `init_uart_clock`
  and the 115200 `init_uart_baud` match the legacy boot options.
- Quick-facts/18 "USB controllers": PASS — PCIe-attached USB 3.0 controller on 4B/400, legacy USB
  2.0 on USB-C as a device with `otg_mode=0` default, XHCI host with `otg_mode=1`, no USB 3.0
  controller on CM4 (`otg_mode` section). Consistent with the processor page's PCIe link to the
  USB ports.
- Quick-facts/19 "Mini UART": PASS — base 0x7E21_5000 shared with SPI1/2, AUX_MU_IO_REG +0x40,
  AUX_ENABLES +0x04 (Table 2, p. 8). Bit 0 gating register access and the immediate-receive
  warning (Table 4 and following text, pp. 9–10; §2.2, p. 10). AUX_MU_CNTL bits 0/1 reset 1
  (Table 13, p. 14). Core-clock dependence ("Mini UART and core frequency").
- Quick-facts/20 "Timers": PASS — core timer IRQs (§6.2.1). ARM_CONTROL bits 7/8 and reset 0
  (Table 105, pp. 92–93). System Timer base, 64-bit counter and four compare channels (§10.1,
  p. 142), VC 0–3 (Table 102). ARM timer base, +0x400 register offsets, variable clock and the
  System Timer advice (§12.1–12.2, Table 192, p. 159). CNTFRQ_EL0 not interpreted by hardware
  (DDI 0487 M.d §D24.10.1).
- Quick-facts/21 "ARM_LOCAL block": PASS — base and Low Peripheral address, control registers,
  IRQ/FIQ_SOURCE at +0x60/+0x70 (Table 104, pp. 92–93). Sixteen mailboxes with MBOX_SET00 at +0x80,
  distinct from the ARMC/VPU mailboxes (§13.1–13.2, p. 163).
- Quick-facts/22 "Clocks and power": PASS — Clock Manager controls the UART clock (§11.1, p. 144),
  and only the GP clocks are described (§5.4, p. 81; no other CM_ registers in the document).
  Channel 8, tags 0x00030002/0x00030047/0x00038002 and their semantics, rate 0 for a missing clock,
  IDs 1/2/12 and base-clock meaning all match the wiki "Clocks" section.
- Quick-facts/23 "VideoCore mailbox transport": PASS — register offsets (Mailboxes, "Mailbox
  registers"). 28/4-bit split, 16-byte alignment, response in place, buffer and tag layout,
  response codes, host byte order (Mailbox property interface, opening sections). Physical
  addresses on the property channel (Accessing mailboxes, "Addresses as data").
- Quick-facts/24 "Mailbox buffers below 4 GB": PASS — the premises (28-bit address field above a
  4-bit channel, 16-byte alignment) are in the property-interface opening sections, and 2^28 × 16 =
  4 GB follows. The bullet is tagged `[inference]` with a TODO.
- Quick-facts/25 "GPIO and pinmux": PASS — 58 GPIOs in banks 0–27/28–45/46–57 and four interrupt
  lines (§5.1, p. 65). Base and register offsets (Table 63, p. 66). Pull encoding (Table 90, p. 74).
  VC 49–52 "GPIO 0–3" (Table 102), GIC per Figure 7.
- Quick-facts/26 "Peripheral memory ordering": PASS — barrier placement and the interrupt-handler
  rules match §1.3 (pp. 6–7). Normal Non-cacheable over-read/merge and Device memory for
  peripherals match A72 TRM §6.4.1 (p. 6-291).
- Quick-facts/27 "DTB runtime patching": PASS — DTB choice by board revision, edits, config.txt
  parameters and overlays, pointer to the merged tree ("Device Trees, overlays, and parameters").
  `/chosen` firmware parameters ("Firmware parameters").
- Gotchas/1 "The GIC and ARM_LOCAL bases are not legacy addresses.": PASS — "every other
  peripheral address in the datasheet is a legacy master address" is the datasheet's own scope
  (§6.5.1 and §6.5.2, p. 92: "unlike other peripheral addresses in this document, this is an
  ARM-only address and not a legacy master address"; §1.2.4, p. 6 says the same of the
  document's peripheral addresses). The full-map and Low Peripheral figures in §1.2.3 are region
  bounds, not peripheral addresses, and §13.2's restatement for ARM_LOCAL agrees. Both bases,
  0x4_C004_0000 and 0xFF84_0000 for the GIC, match §6.5.1. The earlier overstated-scope FAIL is
  resolved.
- Gotchas/2 "One GIC line serves many blocks.": PASS — the groupings and status-register advice
  match §2.1, §6.2.4 and Figure 6. The ETH_PCIe lines reach the GIC individually (Figure 7), and
  the legacy controller gets only their OR on VC 58 (§6.2.5 text, p. 89).
- Gotchas/3 "Peripheral mode is a three-way agreement.": PASS — legacy boot options,
  `arm_peri_high`: enabling high peripheral mode without a compatible device tree "will make your
  system fail to boot", and "currently ARM stub support is missing, so you will also need to load
  a suitable file using `armstub`". The bullet attributes the stub statement to the documentation
  and no longer claims a stub mismatch stops the boot. The earlier FAIL is resolved.
- Gotchas/4 "Pulls are set through `GPIO_PUP_PDN_CNTRL_REG0`–`3`.": PASS — they are the only pull
  registers in Table 63 (p. 66). Two bits per pin and the read-back of the current pull state
  match Table 90 and its description (p. 74).
- Gotchas/5 "Legacy DMA reaches 1 GB at a time.": PASS — the window is moved with "the PAGE or
  PAGELITE bits" (§1.2.4, p. 6). ENABLE.PAGE (27:24) sets the 1 GB page for "the 30-bit DMA
  engines (DMA0-6)" and PAGELITE (31:28) for "the DMA Lite engines (DMA7-10)" (Table 62, p. 60),
  one field per group, so the setting is shared across the group. The L2 aliases at 0x0 and
  0x8000_0000 "can't be moved, and are limited to the first 1GB of SDRAM" (§1.2.4, p. 6). The
  earlier FAIL is resolved.
- Gotchas/6 "The mini UART's baud rate follows the core clock.": PASS — the UARTs page, "Mini UART
  and core frequency": the baud changes with the core clock and fixing the VPU clock is the remedy.
  The PL011 choice follows from the page's comparison of the two UART types.
- Gotchas/7 "Not the Pi 5 chip.": PASS — the BCM2712 processor page names it the BCM2711's
  successor, used in the Raspberry Pi 5 family.
